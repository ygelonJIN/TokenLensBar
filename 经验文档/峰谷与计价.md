# 峰谷与计价

**什么时候读**：改价格表、加模型、核对账单、动 `is_off_peak` / `event_cost`，或发现金额对不上时。

## 官方口径是什么

**什么时候用**：不确定某个时段算峰还是谷、不知道空闲价怎么来。

- 两档：空闲 / 高峰。**空闲价 = 高峰价的一半**，价格表里两档都要写。
- 高峰：北京时间**周一至周五**（不含中国法定节假日）`09:00–12:00`、`14:00–18:00`。
- 其余全是谷：午休、夜间、周末、法定节假日全天。
- 单位是「元 / 百万 tokens」（`prices.json` 的 `currency` 决定，美股价表要换算，见「坑 2」）。
- 官方只列三列：缓存命中、缓存未命中、输出。

核对页：<https://api-docs.deepseek.com/zh-cn/quick_start/pricing/>（中文页是人民币价，英文页是美元价）。

## 一次请求的钱怎么算

**什么时候用**：改 `event_cost`，或怀疑公式漏了某一桶。

```
cost = (cache_hit × 命中价 + cache_miss × 未命中价 + output × 输出价) / 1e6
```

- 三桶互不重叠。DSH 日志里 `inputTokens` 与 `cacheReadTokens` **是并列的**（实测会出现 cache 比 input 大的情况），
  采集时归一化成「输入包含缓存」，算钱时再减回去（`cache_miss = input - cache_read`）。
  搞反就会把缓存部分按全价再算一遍，历史实测差过 8 倍。
- `cache_write` 官方**没有单列价**。DeepSeek 是自动缓存，写入不单独收费；
  `prices.json` 里 `cache_write` 默认 0，不要拿未命中价顶上——那是重复收费。
- 推理 token 不单独计价，已含在输出里，不要另加一列。

## 峰谷判定在哪、按什么时刻

**什么时候用**：要改判定规则，或解释为什么历史账单没变。

- 实现：`tokenlensbar.py` 的 `is_off_peak(ts, prices)`，被 `event_cost` 调用。
- **按事件自己的时间戳**判，不是「现在几点」——所以历史账单不会因为今天调价或今天几点而变。
- 支持两种写法：新写法 `peak_windows`（只列高峰，其余算谷），老写法 `windows`（直接列谷）。
- `peak_only_agents`：有些来源只记「会话最后活动时间」，分不清峰谷，这类整体按**高峰价**算，宁高不低。
  目前是 `["hermes"]`。
- 周末和节假日整天空闲；调休上班的周末仍按周末算（不额外判断补班）。

## 跨峰谷边界的长请求

**什么时候用**：一条请求从 11:58 跑到 12:06，或 13:55 跑到 14:03，怀疑归错段。

官方按**请求发出时刻**计价。DSH 里 `step/start` 带发起时刻，`assistant/message` 带的是答完时刻。

- 采集器（`DshAdapter.parse`）先扫 `step/start`，记下 `(turn, step) → 发起秒`；
  `assistant/message` 用它当 `ts`。没有 `step/start` 的旧会话回退到消息时刻。
- 入库是 upsert，**只改写 `ts`**：`insert ... on conflict(id) do update set ts=excluded.ts`。
  口径切换后重扫一遍旧会话就把历史修正了，不用删库、不用手工迁移。
- `@local/usage-cost` 插件也按 `step/start` 分桶，两边口径一致。
- 回归在 `tests/test_scan.py`：有 `step/start`、缺 `step/start`、重扫改写 ts 三条。

## 改价格之后历史会不会变

**什么时候用**：调价后担心旧账单被改写。

不会。**采集只存 token 数，不存钱**；成本在读取（面板、report、看板）时按当前价格表现算。
多段价格用 `prices.json` 里每个模型的 `from` 字段按事件时间自动选版本。

代价是每次读取要重算一遍：当前量级约 5 微秒/条，全量几十毫秒，可以忽略。

## 四个计价坑

**什么时候用**：第一次接新来源，或金额明显不对。

1. **输入是否含缓存**。Codex / DSH 归一化成「含缓存」，Hermes 是独立两列。
   采集时统一归一化，否则差得离谱。
2. **美元价表混进人民币场景**。Hermes 自带的 `estimated_cost_usd` 默认关掉（`use_source_cost: false`），
   一律用本地单价表重算；`currency` 和价表必须一致。
3. **午休不是峰**。12:00–14:00 是谷，容易按「上班时间」想当然算成峰。
4. **节假日表要每年补**。国务院年初公布，`prices.json` 的 `holidays` 手动加；
   现在只写到 2027-01-03，2027 年春节之后的日子还没补。
